# S2: Panel + Theater

**Status:** not run · **Date:**

## Steps

1. `./install.sh` (adds the shortcut through the DevTools port). Note whether the shortcut
   appears without restarting Steam.
2. Launch "Stream Frame" from the library in the headset.
3. Check `~/.local/state/stream-frame/launcher.log` for the exec line and any errors
   (`gameoverlayrenderer.so` must not be in `LD_PRELOAD`).
4. Confirm: own panel (`valve.steam.desktopgame.<appid>`), laser pointer clicks, SteamVR keyboard
   types, audio plays.
5. Dashboard → View in Theater; then passthrough background with the Arcturus camera (colour).
   Capture with `tools/frame-shot.sh`.
6. The default is now the `.deb` Chrome (see S4). For comparison, `./install.sh --backend=flatpak`
   and repeat: does `flatpak run` land on `:0` with `--ozone-platform=x11`?
7. Does the window get a panel without `lib/tag-window.sh`? (Set `TAG_WINDOW=0`, relaunch.)
   Check with `DISPLAY=:0 xprop -id <wid> STEAM_GAME`.
8. Closing: close the panel from the SteamVR dashboard, then from the Steam library (*Stop*).
   Does Chrome actually exit (`pgrep -f stream-frame/profile`), and does the phone server
   (`remote.py`) stop with it? Observed 30 Sep 2026: after closing in the headset, Chrome and
   `remote.py` were still running 8 minutes later.
