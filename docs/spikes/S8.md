# S8: Steam build in the Steam Linux Runtime (tested with the SteamOS Devkit Client)

**Status:** in progress · **Date:** 30 Sep 2026

Distribution goes through official Valve channels only: the Steam Store (Steamworks). A Steam
build installs files only and runs Linux ARM64 titles in the Steam Linux Runtime 4 container, so
Stream Frame must set itself up on first launch and start Chrome outside the container. This
spike checks that with Valve's **SteamOS Devkit Client**, which installs a build the same way
(as a Devkit Game) before anything goes to Steamworks.

## Already known (30 Sep 2026, over SSH)

- A Devkit Game is `~/devkit-game/<name>/` plus `<name>-argv.json` (start command, e.g.
  `["run.sh"]`) and `<name>-settings.json`; for ARM64 Linux titles the runtime is
  `{"steam_play": "0", "compat_tool": "SteamLinuxRuntime_4-arm64"}` (a pressure-vessel container).
- Inside that container: the home folder and the network are shared;
  `/usr/bin/steam-runtime-launch-client --alongside-steam --host` runs commands on SteamOS itself
  (host has `DISPLAY=:0`, `zenity` and `kdialog`). The `.deb` Chrome would miss only
  `libatk-bridge-2.0.so.0` and `libatspi.so.0` inside the container.

## Steps

1. Close Stream Frame.
2. In the SteamOS Devkit Client, upload the folder `tools/s8-probe/` as a new title
   (for example *stream-frame-s8-probe*), start command `run.sh`, runtime
   *Steam Linux Runtime 4.0 (arm64)*, Steam Play off.
3. In the headset, launch *stream-frame-s8-probe* from the library. The probe:
   - logs its surroundings to `~/.local/state/stream-frame/s8.log`,
   - shows a test window for 10 seconds (on the host, with zenity),
   - then starts the installed Stream Frame on the host.
4. Check: did the test window appear in the headset? Did Stream Frame open in its own panel?
5. Close it with the library's *Stop*. Then over SSH: is Chrome still running
   (`pgrep -f stream-frame/profile`), and what does the end of `s8.log` say?
