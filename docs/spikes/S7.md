# S7: Send a link from a phone

**Status:** not run · **Date:**

## Steps

1. Launch Stream Frame. The start page shows *Send links from your phone: http://<ip>:8765*.
   If not, open the gear icon → Server and note the status line; check `launcher.log` for
   `remote:` lines.
2. On a phone on the same Wi-Fi, open the address. Does the page load? If not, from the Frame
   over SSH: `ss -ltnp | grep 8765` (listening?) and `sudo iptables -S` / `sudo nft list ruleset`
   (is a firewall blocking it?).
3. Try the `http://<hostname>.local:8765` address the Server tab suggests, on iPhone and Android.
4. Paste each example share text and check the title opens in the panel:
   - Netflix: `https://www.netflix.com/us/title/70301870?s=i&trkid=13747225&shareType=Title&…`
   - Prime Video: `https://watch.amazon.com/detail?gti=amzn1.dv.gti.44a9f6f7-b5de-4153-38e2-919dca60a29f&…`
     plus its sentence. Does the `amazon.com/dp/…` page it redirects to play?
   - HBO Max: `https://play.hbomax.com/topical/f7ebcd02-6641-4ec5-a392-07e58196808f?…` plus its sentence.
5. Start a film, send another link: does the *Open this … link?* prompt appear over the
   fullscreen player, and do A (open) and B (keep watching) work with the controller?
6. Turn the confirmation code on, enter it on the phone, change the port, turn the server off:
   does each take effect immediately?
7. Leave Stream Frame open for over an hour with no activity, then send a link. Does it still
   arrive (the background worker's WebSocket stayed up, with the Flatpak and with the `.deb`)?
